## 1 — Probe measures the pin; it no longer replaces it

`/api/probe` wrote its own target into `model_pin`, so clicking **Run fast probe**
swapped the user's model for `openai/gpt-4o-mini` and, on failure, 409'd every
later chat with no UI escape.

- `ProbeIn.provider` / `.name` now default to empty, meaning *"measure whatever is
  pinned"*. The button sends `{}`.
- `/api/probe` no longer writes `model_pin`. It writes the card only.
- New `POST /api/probe/clear` resets a failed verdict, surfaced in the sidebar as
  **Clear verdict & unblock chat** whenever a probe returns anything but `agent`.

Live, on the pinned local model:

```
PIN BEFORE: af-unsloth-llama-3-2-1b-instruct-gguf:latest
POST /api/probe {"provider":"openrouter","name":"openai/gpt-4o-mini","mode":"fast"}
PIN AFTER : af-unsloth-llama-3-2-1b-instruct-gguf:latest     <- survives
```

And the full recovery loop, in the browser:

```
Run fast probe -> "af-unsloth-...: chat_only - lo95=0 - steps=1"   (pin unchanged)
POST /api/chat -> 409 probe verdict chat_only: bad_tool
Clear verdict  -> "Verdict cleared. Chat is unblocked."
POST /api/chat -> 200
```

## 2 — A pull only succeeds when the tag actually resolves

Ollama answers **HTTP 200** and reports failure inside the NDJSON stream, so
`raise_for_status()` passed and the worker declared success unconditionally.

- Any streamed event carrying `error` now fails the job immediately.
- Success additionally requires the tag to appear in `/api/tags`, which also
  catches a stream cut short mid-download.
- `list_or_none()` distinguishes *"Ollama says it is absent"* from *"Ollama could
  not be reached"*, so an unreachable daemon never fails a good pull.

```
POST /api/catalog/pull {"name":"definitely-not-a-real-model-xyz"}
GET  /api/catalog/pull/7cf69ef12a8b
  -> {"status":"error","percent":0.0,
      "error":"pull model manifest: file does not exist","done":true}
PIN AFTER BAD PULL: af-unsloth-llama-3-2-1b-instruct-gguf:latest   <- untouched
```

Previously: `{"status":"success","percent":100.0}` and the phantom model pinned.

## 3 — Enumeration is graded only when the question names a term

The `demurrage` fallback and the unanchored `"list" in question` test are gone.
Grading now happens only when the question actually names a term to enumerate.

| Question | Before | After |
|---|---|---|
| `List the files in this folder.` | FAIL incomplete_enumeration | not graded, pass |
| `Show me a playlist` | FAIL incomplete_enumeration | not graded, pass |
| `Which files mention demurrage?` | — | graded, recall 1.0, **precision 1.0** |

The empty-ground-truth branch of `enumeration_recall` now also returns
`precision`, which it previously omitted.

## 4 — Files added after launch are marked, and re-indexing is one click

`/api/files` now returns `indexed` per file, and the sidebar has a **Re-index this
folder** button wired to the `POST /api/ingest` that already existed.

```
drop DOC-014-BRONT.txt into the workspace
sidebar: "1 file(s) are not indexed yet - the agent cannot search them."
         DOC-014-BRONT.txt  [not indexed]
click Re-index -> "Re-indexed this folder: 14 file(s), 14 chunk(s)."
sidebar: "All listed files are indexed."
```

`grep.json` is rewritten by every ingest, so the scorer's ground truth stays in
step without extra work.

## 5 — The llmfit browser opens on models you can actually get

New `downloadable` filter on `browse_llmfit` and `/api/catalog/llmfit`, on by
default in the modal as **downloadable only**, plus a score sort that ranks
actionable rows above `UNRESOLVABLE`.

```
BEFORE  offsets 0 / 400 / 2000 / 6000 -> 80 x UNRESOLVABLE, 0 downloadable
AFTER   default view -> "Showing 46 of 46 (catalog 11271)", every row actionable
        unfiltered first page -> 46 NO_RUNTIME + 14 INSTALLED first, then the rest
```

## 6 — Bare tags and `:latest` compare equal

`normalize_tag()` in the runtime and `normTag()` in the UI. `_row_for` compares
normalised names on both sides. Live, with the pin stored bare and `/api/tags`
reporting `:latest`, exactly one card is highlighted and exactly one button reads
"Using" — in both the sidebar and the Ollama modal.

## 7 — One percentage, no control characters

`strip_ansi()` cleans the llmfit CLI line before it is stored. The UI strips any
percentage already inside the status text and renders a single figure of its own,
next to a real progress bar. A **Cancel download** button is now wired to the
cancel endpoints for both the Ollama and llmfit paths.

The progress-rendering path is verified; a full ~1 GB llmfit download was not
re-run in this pass.

## 8 — The meter reports the budget that is actually enforced

`run_loop` now carries the real prompt/completion split out of the graph, and
`add_usage` stores it instead of booking every token as a prompt token. The header
shows the per-turn budget the loop enforces alongside the session total:

```
turn 2545 / 32000 tokens - session 5008 - $0.0000 / $0.50
```

## 9 — An unprobed pin says so

`{"per_step_success_lo95": 0.5, ...}` is replaced by
`{"per_step_success_lo95": None, "measured": False}`. `stats.effective_lo95()`
maps that to a documented `UNMEASURED_LO95 = 0.40`, which still yields the 3 steps
v1 needs without ever being mistaken for a measurement. Live traces now report
`per_step_success_lo95: 0.4` for unprobed pins rather than a fabricated `0.5`.

## 10 — A misaddressed tool call recovers, in English

- `schema_reject` carries a `detail` sentence naming the tool and its real
  arguments.
- When rejected args validate against exactly one sibling read tool, the call is
  re-dispatched there and tagged `rerouted_from`. Empty args are never rerouted —
  those are a missing-argument error, not a misaddressed call.
- `"which files"` reaches the fallback, and the fallback now picks **retrieval**
  when the question names a term.

That last point mattered: adding `"which files"` alone routed *"Which files mention
demurrage?"* to `fs_list`, which returned all 13 files and scored recall 1.0 while
answering nothing. With the retrieval branch, on a 1B local model:

```
tools: rag_search (fallback, query="demurrage")
Found matches in 4 files:
- DOC-001-NEPTUNE.txt ... - DOC-010-ATLAS.txt   (with quoted evidence per file)
enumeration recall 1 - pass     (ground_truth 4, returned 4, precision 1.0)
```

## A — New, High: a fresh workspace wrote files without asking

`gateway/spec.py` defaults `fs_write` to `deny`, but the shipped
`templates/document-query/agentspec.yaml` overrode it to `allow`. Every new
workspace therefore started with the agent able to create and overwrite files in
the user's document folder with no confirmation — while the sidebar presented
"Ask - show a diff first" as the cautious option the user could opt into.

The template now ships `ask`. The confirm-diff flow stays discoverable and a first
run cannot write unprompted. Verified live on a clean workspace:

```
GET /api/health -> fs_write = ask
"Write a file called summary.md ..." -> diff modal "Confirm new file - ./summary.md"
Apply change -> summary.md on disk (139 bytes)
```

## B — New, Medium: phantom READY rows

`in_download_cache()` matches names by fuzzy prefix, so safetensors-only repos
collided with unrelated downloaded GGUFs and were marked `INSTALLED`. They
rendered with a green **ready** badge whose only action was a disabled
*"No GGUF files in repo"* — 14 of them in the default llmfit view.

A cache hit now only counts as installed when something can actually run it (an
Ollama tag, or a resolvable GGUF). Otherwise the row falls through to
`UNRESOLVABLE` with its real reason, and the downloadable filter hides it.

## Low items

Fixed: raw `fits wont_fit` enum (now "won't fit", consistent casing, as a coloured
pill); fit computed from total rather than instantaneous free RAM, so labels stop
flipping between page loads; empty state keyed on whether a filter is active
rather than on the tab; **New chat** button plus `POST /api/session/reset`;
`GET /favicon.ico` returns a 1x1 GIF instead of 404; modal footer no longer
overlaps the last row and the header no longer wraps; a responsive breakpoint at
980px stacks the sidebar above the chat with no horizontal scroll.

**Not fixed — API key at rest.** `openrouter_key` is still stored in plaintext in
`<workspace>/.agentforge/app.sqlite`, inside the folder the user pointed the tool
at. No endpoint echoes it back and `.agentforge/` is gitignored in this repo, but
not in an arbitrary `--dir`. A real fix needs OS keyring storage (DPAPI on
Windows), which is a larger change than this pass.

## UI

`gateway/static/index.html` was rebuilt minimalist: near-white ground, hairline
rules instead of boxed cards, sidebar sections separated by whitespace, quiet
label-style badges, and a single solid button per surface. Colour is spent only
where it carries meaning — green for a ready model, amber for a marginal fit or
an unindexed file, red for "won't fit" and for write-enabled, and one blue rule
marking the active model. Bubbles are gone from the agent's turn: the reply is
plain prose and only the user's turn takes a surface. A
`prefers-color-scheme: dark` variant maps every token onto near-black.

Three defects were found and fixed while building it: the shell used
`calc(100vh - 59px)` against a header that measures 67.5px, giving the page a
second scrollbar beside the sidebar's own (now a flex column); the cost cap
rendered as `$0.5`; and a repeated identical tool call printed the whole answer
twice (see below).

Console across the whole session: **no errors** other than the 409 deliberately
triggered while testing the probe recovery path. The favicon 404 is gone.

## C — New, Medium: a repeated tool call printed the answer twice

Observed live on `granite3.1-moe`: the model called `rag_search` with identical
arguments on two consecutive steps, and `summarize_results` rendered both, so the
four matched files and all their quoted evidence appeared twice in one reply.

```
tools: rag_search, rag_search    (both {"query":"demurrage","limit":5})
answer blocks containing "Found matches in 4 files": 2
```

`dedupe_results()` now drops repeats of the same call with the same arguments
before rendering. The traces still show what the model actually did; only the
prose stops repeating. After: same two calls, **one** answer block.
